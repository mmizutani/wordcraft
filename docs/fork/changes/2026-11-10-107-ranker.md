# The assistant can rank notes from past contract cases by topic, deal facts and the power balance, in English and Japanese

- **Issue:** #107, AS8.1
- **Upstream doc it would have touched:** `ROADMAP.md`
- **Not verified:** ranking quality on real cases; the corpus is synthetic and written by the implementer

`crates/assist/src/cases/` holds the pure core of case memory: the typed record (`record.rs`), tokens, a topic table and a per-query BM25 (`text.rs`), and `score` = relevance × fit × transfer × age × place × standing (`recall.rs`). Nothing reads or writes a file yet, and no window or command uses it; that is the next pull requests.

The corpus test was the go/no-go for typed similarity, and it passed with the design's table unchanged: with the person weaker now, a concession won while weaker outranks a wordier one won while stronger by about 2.8x, while word overlap alone ranks them the other way. A Japanese query finds an English note on the same topic and the reverse, a pitfall scores the same whatever the stance, and a query of hiragana alone matches nothing.

Two things the design didn't say. `Topic` has no `Other` variant, because every topic must carry an English and a Japanese term and `Other` can't. The pitfall floor (a pitfall is recalled for a query with no topic, so "review this draft" finds traps) applies only when the query has at least one searchable word, or a hiragana-only query would recall every pitfall. The `recall` and `text` modules are public, since the crate has no caller for them until recall reaches a turn.

`wordcraft_doc::is_cjk_word` is now public, and `wordcraft-assist` depends on `chrono` for dates.
