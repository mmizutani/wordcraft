# A lesson you keep on a card reaches every client's cases, and nothing else of a case leaves its client

- **Issue:** #107, AS8.7
- **Upstream doc it would have touched:** `ROADMAP.md`
- **Not verified:** the pane on a real screen; the tests drive it headlessly. No real-model run: whether a model writes a `lesson` marker is for the owner's next run of `case_eval`.

Until now recall read the bound case and the same client's other cases, and nothing crossed a client. The owner decided (#107, decision 2) that only lessons the person approved, with names stripped, cross clients; records and notes stay inside one client. This change is that.

**The store.** `assistant-lessons.json` sits in the settings folder beside `assistant-cases/`, read and written by the same `Shelf`, under its own lock file, in one rename, with the same 1 MiB cap checked before the file changes, and every persisted type denying unknown fields. A `KeptLesson` is an id (`l3`, never reused), the text (at most 400 characters), its `Applies`, its topics, whether it is off, use counts, and the case it came from, which stays on this computer: it is never put in an item and is cleared when that case is deleted and the lesson kept. `Applies` is the design's: kind, side, paper, counterparty kind, law, stance and year, `Copy` so the compiler shows it holds no text, with no size band and no day (graft 4), and it now serializes with `deny_unknown_fields`, so a file with a `size` key under `applies` reads as damaged rather than carrying it. A damaged file reads as empty and damaged, a turn recalls no lesson from it and says so, and the person's next write moves it aside as `assistant-lessons.json.damaged` before writing. There is no model op on lessons: `LessonOp` has Keep, Edit, Remove, Off and CaseDeleted, and every one takes the person's `Click`.

**How one is made.** Four person-only commands under the existing prefix, `assist.memory.lesson.keep`, `.edit`, `.off` and `.remove`, hand the window `memory.lesson.*` requests through the one guard, so a script, a macro's step and the control channel's click are refused as the case commands are (the registry test counts 18 now, and the window test that tries every write without a click gained the four). A model proposes one with `{"op":"lesson","text":…,"notes":[ids]}` in a `[[case]]` marker, which `route` turns into a card under either `MODEL_WRITES` setting; `CASE_ASK` gained the example, and the test that parses every example covers it. A confirmed note's row on the case page has **Make a lesson**, which opens the same card on the page, filled from the note.

**The card.** It shows the exact text (**Edit** turns it into a box), flags any word of it that names a party of the case, both folded as the tokenizer folds (case and full-width ASCII): a party's whole name anywhere in the text, or any word of a party's name as a word of the text. While a name is flagged **Keep** is disabled until **Keep it with the name** is ticked. Below the text, every fact of `Applies` that is set is a ticked checkbox named as the case page names it; unticked, that fact is dropped from what travels. It says "This goes to every client's cases. Nothing else of this case does." **Keep** runs `assist.memory.lesson.keep` with the text, the ticked facts and the case's id; **Not this** on a card under an answer runs `assist.memory.case.cardDismiss`, and on the page closes the form. The card's facts are the case's as of the first note the proposal names, else today, so the stance is the one the lesson was learned under. A card under an answer is built from the conversation's own case, as a marker's note is routed, never the document's current binding; the window keeps a waiting card's text and ticks by card id, and since card ids start again with each conversation, that cache is cleared when a conversation starts, ends or is rebound, and a cached card is reused only while its case is still the conversation's, so a card from an earlier conversation can't lend another case's party names or facts to a new proposal.

**Recall.** `Pool` reads the lessons file beside the wall and adds every lesson that isn't off as a `Candidate::Lesson`, scored by the same `score`: relevance from its text and topics, `fit` from its `Applies`, `transfer` from the stance it was kept under against now, age from the first day of its year (none, it doesn't age), place weight 1.2 between this case's 1.5 and the same client's 1.0, confirmed. `Candidate` became an enum for this, with `note()` for the corpus tests. Its item is `{"id":"l3","place":"a lesson the person kept","kind":"lesson","text":…,"year":…,"contract":…,"side":…,"paper":…,"counterparty":…,"law":…,"balance":"then …, now …","confirmed":true}`, with no case, client, title or name. Details › Recalled shows it as "a lesson you kept".

**Deletion.** `Shelf::delete_case` takes `keep_lessons`. Under the lessons lock, before the case's own lock, the lessons kept from the case are removed, or stay and lose the link; a crash between the two leaves the case present, and deleting again converges. The page's delete prompt lists those lessons with **Delete these too** ticked. A client can only be deleted once it has no case, so its cases' lessons were asked about case by case; the wall delete itself touches no lesson. Details › Case lists every lesson with **Edit**, **Off** or **On**, and **Remove**, and File › Options › Assistant does when no document is open.

**Tests.** `cases::lessons::tests`: a party's name is flagged folded and other words aren't; a kept lesson's file has no `size` key and one with it reads as damaged. `cases::store::tests`: a deleted case's lessons go with it or stay unlinked; a damaged lessons file moves aside on the person's next write; the text limit and never-reused ids. `cases::recall::tests`: a kept lesson is an item with no case, a lesson that is off isn't read, and a damaged file sends none and says so. Window tests: a lesson kept from one client reaches another client's turn while that client's notes, the source case's notes, its ids and its party's name never do (canaries), and `assist.memory.case.delete {"keepLessons": true}` leaves the lesson unlinked; a model's `lesson` marker is a card that stores nothing until the person's Keep, with the control channel's click on Keep and on Not this storing nothing and leaving it waiting; the card flags a party's name, Keep waits for the second confirmation, and an unticked fact stays home while the ticked ones travel; a lesson card opened in a conversation on one case, then a new conversation on another case whose model proposes a lesson with the same card id, shows the second case's facts and flags its party, never the first's. The engine's registry and shape tests cover the four commands and `keepLessons`.

One thing outside the design: `Job::Turn` now boxes its `RecallAsk`, since `Shelf` grew a second path and clippy's variant-size limit tripped; nothing else changed there.
