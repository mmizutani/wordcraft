# A file you bound to a case is bound again when you open it, after a restart too

- **Issue:** #107, AS8
- **Upstream doc it would have touched:** `ROADMAP.md`
- **Not verified:** the pane's line on a real screen (the tests check the binding and the flag the line reads, headlessly); Windows paths, which the tests don't run on.

Until now the binding lived only in the window's memory, keyed by the per-process document id, so after a restart recall and case notes silently stopped applying until the person bound the document again.

The person's bind is now also kept for the document's file in `assistant-cases/bindings.json`, beside the walls: `{"version":1,"files":[{"path":…,"wall":…,"case":…,"blocks":[…]}]}`, keyed by the file's canonical path. Nothing goes into the document, whose `custom.xml` anyone can write. The format is closed like `case.json`: `deny_unknown_fields`, one version, at most 200 files, paths of at most 4 KiB as written, at most 32 block ids each, and 1 MiB in all (a test fills every limit with paths whose backslashes double when escaped). A file that breaks any of that binds nothing, and the person's next bind or unbind moves it aside as `bindings.json.damaged` before writing, as `assistant-memory.json` is. Writes take `bindings.lock` and replace the file in a rename through `atomic.rs`, as the cases do.

Only the person writes it: `assist.memory.case.bind`, `.new` and `.unbind` keep or forget the shown document's path after the in-memory binding changes, inside the same person-only commands as before, so no guard changed. Delete forgets every file bound to the case between the rename to trash and the folder's removal, and the sweep that finishes a delete a crash interrupted does the same before removing the trash, so a crash at either point leaves nothing bound to a deleted case. Deleting only a case's record (`log/`) goes through the same trash as `<case id>-log`, which names no binding, so the file stays bound, and a case deleted with its record in it still forgets its files; a test covers both and the sweep of a record's interrupted delete. A binding whose case is gone some other way is dropped when its file is opened, without waiting for another window's lock.

The window looks a document's file up once, the first frame it is shown (and before a turn starts, for a file opened on the same frame). Once per document is the rule that keeps a copy from inheriting: Save As keeps the document's id, so a copy saved under a new name is never looked up, and its path has no binding for the next time. The same rule means a document bound before its first save is bound only in this window, and the docs say to bind it again once it has a file. A binding that came back with the file shows "Bound to <case> as when you last had this file open" above the conversation, with **Unbind**, and under the case's title in Details › Case. There is no separate Change action: Unbind then shows the list of cases to bind another.

A path alone doesn't say which document is there: another client's document saved over a bound path would take the binding, and every turn would send the first client's facts, balance, plan and recalled notes to the model while it works on the second client's text. So a binding keeps up to 32 of the document's block ids, spread evenly over it, and the file binds again only when the opened document still holds one of them. Word files keep block ids (`w14:paraId`, `wc:blockId`), so an edited document keeps binding while another document at the path, even one with the same text, binds to nothing; a unit test and a window test with two windows cover it, and both fail without the check. The cost is that a document whose every marked block was deleted, or a file in a format that keeps no block ids (text, Markdown, RTF, ODF, HTML), binds to nothing until the person binds it again.
