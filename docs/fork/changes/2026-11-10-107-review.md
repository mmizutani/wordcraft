# Review this case: the consolidation pass as one turn the person can see

- **Issue:** #107, AS8.10
- **Upstream doc it would have touched:** `ROADMAP.md`
- **Not verified:** the button and the cards on a real screen; the tests drive the window headlessly. No real-model run: whether a model answers a review with the four verbs is for the owner's next run of `case_eval`.

The memory design's last layer is a consolidation pass over the others: check the notes against the record, retire what no longer holds, focus on what is likely to have changed, and ask what the record can't answer. Graft 1 of the design made it a visible turn rather than a hidden run: no worker, no sheet, no `run_alone`. This change is that turn.

**The ask.** `assist.memory.case.review {}` is a person-only command under the existing prefix (the registry test counts 21 now; `person_only`, the macro guard and the control channel's refuse it with no guard edit, and Search leaves it out as it does the deletes). It hands the window `memory.case.review`, which goes through the one guard and then `assist::review`: the same path as `assist.ask`, with the fixed `REVIEW_ASK` (a constant in `marker.rs`, under 4 KiB, a test parses every example in it) as the prompt and `RecallAsk::review` in place of the turn's recall. `REVIEW_ASK` is the person's ask, on the prompt channel; `CASE_ASK` and the instructions are unchanged. Details › Case has **Review this case** with a line in front of it saying it spends one request on the person's plan.

**What the turn carries.** `RecallAsk::review(shelf, at, today, alone)` takes the same `Alone` proof as recall, so a review needs the same empty room, and `run` rechecks it after reading as recall does. On the conversation's thread it reads the case (title, facts, balance, plan, every note with id, kind, standing, how and date; never the dismissed hashes) and the most recent record lines up to 96 KiB (`log::recent_records`, newest file first, whole lines, oldest left out and said so; a case with no record reviews its notes alone) and sends them as one `TurnSource` with the `Recalled` framing, so recalled text stays data. Details › Recalled shows the item as "N notes, the balance and plan, and M record lines". Nothing held back as sent before applies to it: a review is asked for whole each time. A damaged case reviews nothing and says why.

**The verbs.** `CaseMarker` gained `Correct { note, text, why }`, `Retire { note, why }`, `Supported { note, evidence }` and `Gap { question }`, and `review_only()` names them. The transcript keeps a review flag, set by `review_turn()` right after the review's ask and cleared at the next `asked`: a review-only marker in any other turn is dropped and counted there, with the ones that didn't parse, and never reaches the window; a review's turn may keep 32 markers rather than 5. `route` turns `Correct` and `Retire` into `ModelWrite::Correct` and `ModelWrite::Retire`, and `Supported` and `Gap` into `Route::Supported` and `Route::Gap`, which are rows and never writes. In `Case::apply_model` a correction of an unconfirmed note replaces its main text and sets its how to the why (`Applied::Edited`); a retirement removes it (`Applied::Removed`); on a confirmed note each is `Applied::Card`, which the window shows as a card whose Keep is the person's `noteEdit` with the main text replaced and the why as how, or their `noteRemove`, with the note as it stands shown on the card. A note id the case doesn't have is `NoSuchNote`, which the window counts as a dropped marker; so a neighbour's or another client's id touches nothing. `Supported` reads the case once and shows a row with the evidence if the note is there, else counts; `Gap` is a row with the question.

**Security review fixes**, each with a test that failed first and a mutation that killed it. (1) The quote index walked JSON only four levels down, and a review item's record lines nest tool details deeper, so a paste of such text wouldn't have been flagged: `strings` now walks the whole item (fix 6), and `a_review_item_puts_every_string_it_carries_in_the_quote_index_and_works_without_a_record` checks every string of the item is in `sent_text`. (2) The first commit gated review verbs on a window flag: now the transcript's own flag drops them before `take_case_markers`, and `a_review_verb_in_an_ordinary_turn_is_dropped_and_counted_and_never_routed` checks the four are dropped and counted in an ordinary turn and routed only in a review's. (3) A correction skipped the dismissal check a new note gets: `model_knows` refuses text the person dismissed, text a review retired, or text another note says, and `a_correction_to_dismissed_or_duplicate_text_is_refused_as_a_new_note_would_be` checks it. (4) A model's retirements went into the person's capped `dismissed` list, so a poisoned document could push the person's entries out and re-note them: `Case` gained `model_dismissed`, its own list with its own cap, which blocks the model only; `model_retirements_never_push_out_the_persons_dismissals` fills it past the cap and checks the person's dismissal still blocks. The person's own `AddNote` still answers to `dismissed`, as it did on `claude/as8-9-record`; that is unchanged.

**Codex review fixes**, each with a test that failed first and a mutation that killed it. (5) `recent_records` parsed every line of a file before its 96 KiB budget applied, and `search_log` collected whole files too, so a large file of short records cost memory in proportion to the file: the search now streams a line at a time and holds only its hits, and a review reads each file back from its newest line and stops once the budget is spent, so lines older than what it carries are neither read nor counted as unreadable; `a_review_reads_the_newest_lines_and_stops_at_its_budget` checks it. Either reads at most `MAX_READ_BYTES` of a file (what the writer can write: 16 MiB of records and one `Dropped` line), since a longer one wasn't written by WordCraft, and counts the rest as one skipped line; `a_file_past_what_the_writer_makes_is_read_only_that_far` checks it. (6) `strings` stopped at depth 128, but a review item wraps a record line, which `serde_json` reads to 127 levels, in two more, so a string in a redline's position nested that deep was sent to the model without being indexed: it now walks with a stack and no depth limit, the work bounded by the item's size, and `a_string_nested_as_deep_as_a_record_line_parses_is_in_the_quote_index` checks such a string is in `sent_text`. (7) From the PR's review bot: the ask's check passed while the case was only read later, on the conversation's thread, so a review whose case couldn't be sent there (someone else can read the document by then, the file is damaged, no room is left to check quotes) still went to the model with the review prompt and no case, spending a request on a review from what the model holds. The thread now makes no request for a review that recalled nothing and ends the turn with "The review was withheld: …"; `a_review_whose_case_cant_be_sent_makes_no_request` checks both a newcomer and a damaged file.

**Known limits.** A review's record lines join the conversation's quote index, so a later change that quotes the conversation's own earlier answer at length is flagged as quoting recalled text; the flag is a row, not a block. A review names notes by `n12` alone, as every marker does, so an id from another case either names nothing (dropped) or this case's note of the same number, which is this case's to correct. The review's 32-marker cap is per turn: a case with more unconfirmed notes than that is reviewed in parts.

**Deviations from the design.** The design's `Correct` carried a `NoteDraft`-shaped replacement; here it carries the main text only, since the kind and the other fields are the note's, and the why becomes the note's how. The design placed the review under its own `Sheet` with tick boxes and one **Apply**; graft 1 replaced that with the normal marker route, and this change follows the graft: rows and cards under the answer, each card its own click.

**Tests.** `cases::marker::tests`: every example in `REVIEW_ASK` parses and covers the four verbs; a correction applies to an unconfirmed note and is a card for a confirmed one; a retired unconfirmed note goes and blocks the model and a confirmed one is a card; `supported` and `gap` are rows under either `MODEL_WRITES`; the two record fixes above. `cases::recall::tests`: the quote index fix above, with `recent_records` keeping the newest lines under its cap. `tests`: the transcript fix above. `assist::cases::review::tests` (the window, against a scripted `Fake`): a correction of an unconfirmed note applies and of a confirmed one is a card that changes nothing until the person's Keep, the control channel's Keep doing nothing; a retired unconfirmed note goes and blocks a re-note and a retired confirmed note is a card; a review verb in an ordinary turn changes nothing and is counted; a note id from another case is dropped and touches nothing; the review turn carries the notes and the record as one data-grade source and nothing of them in the instructions, shows `supported` and `gap` as rows, and is withheld with a second participant; a control-channel click on **Review this case** starts nothing and the person's click asks the review. The engine's registry and shape tests cover the command, and the scripted-writes window test gained it.
