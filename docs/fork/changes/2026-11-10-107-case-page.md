# A document can be bound to a case of a client, whose facts, power balance, plan and notes the person sets in Details › Case, and a turn then recalls from it

- **Issue:** #107, AS8.4
- **Upstream doc it would have touched:** `ROADMAP.md`
- **Not verified:** the owner's try on a real contract, which this version exists for; ui_shot screenshots are on the pull request if the GPU run worked, else the section was checked by the kittest control-click test only

This is the first usable version of case memory. `crates/engine/src/cmd/assist/cases.rs` adds `assist.memory.case.{new,bind,unbind,facts,balance,plan,note,noteEdit,noteConfirm,noteRemove,delete}` and `assist.memory.wall.{new,delete}`, each checking the shape of what it is given (ids of 16 hex digits, a note id `n12`, texts of at most 400 characters, objects of at most 16 KiB) and pushing a `memory.case.<verb>` or `memory.wall.<verb>` request. The names put them under every existing person-only guard with no guard edit: `person_only` (no key, no ribbon place), the macro guard on the `memory.` request prefix, and `memory::write`'s `by_person` check, from which one new arm hands them to `assist/cases.rs::write`. There the objects are parsed with serde into the typed record (`Facts`, `Body`, `Factor`, `Stance`), so a field a record doesn't know or a value outside its list is an error, never a panic; the engine's `junk_params_never_panic` covers the new params too. A registry test asserts that every command whose params say "Yours alone" satisfies `person_only` and the reverse, so a write named outside the prefix can't slip past the guards in silence. `case.delete` and `wall.delete` are out of command search.

The window passes `new_wall` and `new_case` the stamp PR 2 asked for: the process id, the time to the millisecond, and a process-wide counter. `case.new` names a client by id, by name (a wall of that name in the last listing, or a new one) or not at all ("My cases"), and binds the new case to the open document. Binding goes through PR 3's `bind_case`, so a conversation bound to another case ends, its turn stopped; unbinding ends it too. A binding still lives for the document's life in this window, and no id goes into the document. Delete ends the document's conversation first, then `Shelf::delete_case`; the page's next read of a case another window deleted drops the binding and says so.

Details › Case, a section inside the `desktop` block shown only with a settings folder (`assist/cases/page.rs`): unbound, the cases by client as buttons and New case with a client picker; bound, the title and client with Unbind, the facts as `craft_ui::ComboBox` pickers that write as they change plus the law and parties as text with Save, the balance with Reassess (three stances, up to four factors with kind, side and why) and its history, the plan with Edit and Remove, the notes grouped by kind with Edit, Remove and Confirm on an unconfirmed one, Add note with a form per kind, and Delete case asking in place and naming what goes and what WordCraft can't reach. The bound case's file is read when the section shows and at most every 2 s, and again after each write; the listing of every client's cases is a folder scan and runs on a worker, `ModelList`-style, and the last listing stays while a newer one is read. Create by client name before the first listing has come back lists the folder on the spot rather than making a second client of the name. Every write goes through `app.run`, so the control channel's click changes nothing (a kittest test clicks Create both ways). The page's forms (facts, balance, plan, a note, Delete case) record the case they were opened on: rebinding the document closes them unsaved, and a Save for a case other than the bound one is refused with a notice, so text typed for one client never lands in another's file. Enum labels are tables beside the page, translated through `tl!`; the case's own text isn't.

`docs/assistant.md` gets a Cases section after Memory, and Privacy links to it. Deviations from the design: the pane header's **No case** chip, Positions as a table, Record, Review, Close and Lessons are later pull requests; `Close` is the Stage picker in Facts; Delete client is offered only for a client with no cases left, since nothing is lost but the name, and `Shelf::delete_empty_wall` checks the folder again at the delete, since another window may have added a case since this one listed.
