# Past contract cases can be kept on disk, where two WordCrafts, a crash, a damaged file or a model's write never lose or leak one

- **Issue:** #107, AS8.2
- **Upstream doc it would have touched:** `ROADMAP.md`
- **Not verified:** Windows, where a folder may refuse a rename while another window holds a file in it open; the lock sits beside the case folder so that this can work, and the test ran on macOS only

`crates/assist/src/cases/store.rs` is the shelf: `assistant-cases/<wall>/<case>/case.json`, one folder per client (a wall) and one per case, ids of 16 hex digits parsed at every boundary so an id can't name a path outside the folder. Every write takes the case's lock file, reads the file again, applies one typed operation and replaces the file in a rename, so two windows keep each other's notes. A write never creates a folder: a case deleted in another window returns `Gone` and stays deleted. A delete renames the folder to `.trash-<id>` under the lock and then removes it, and the next listing sweeps what a crash between the two left. Folders are mode 0700 and files 0600 on Unix.

The record (`record.rs`) now serializes, with its version, and gained size, language, stage and parties in `Facts`, factors on a balance, note ids (`n12`), a plan, use counts and the hashes of removed notes. A file that can't be read whole, has an unknown version or holds more than the limits (1 MiB, 400 notes, 64 unconfirmed, 32 balances, 400 characters of main text, 120 of `how`, a trap or a guard) reads as what can be read and is moved aside to `case.json.damaged` by the person's next write, as `assistant-memory.json` is; a model's write leaves it alone.

What a model can do is the `ModelWrite` enum, which has no confirm, no facts, no bind and no delete. Its notes are unconfirmed, past 64 of them a new one replaces the oldest never used, a note whose text a note already says or the person removed is a no-op, and a plan over the person's plan changes nothing and comes back as `Applied::Card` for the window to show. `Click` is a zero-sized proof only `Click::by_person(true)` makes, and every person write takes one.

Two things the design didn't say. New ids come from a time string and a counter the caller passes, hashed, with `create_dir` making them unique, because the crate builds for the web, where there is no clock and no random numbers. A balance holds at most four factors, not eight, so that a case at every limit in three-byte characters fits the 1 MiB file; the test builds one. In four-byte characters (emoji) such a case would not fit, and reads as damaged.

`Lock` and the atomic write moved out of `memory.rs` into `atomic.rs`, which both files use; the memory tests are unchanged. Nothing in the window or the engine uses the shelf yet.
