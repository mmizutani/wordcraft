# The fork has upstream WordCraft up to 2922fe56, so an MCP client never runs a state-changing command twice when its reply is lost

- **Issue:** none; an upstream sync like #65
- **Upstream doc it would have touched:** none: the read-only docs take upstream's text
- **Not verified:** the macOS-only and font-dependent tests listed below on a host with a GPU, CJK, Arabic and Thai fonts and craft-fonts; the ACP assistant tests with the real `~/Library/Caches/WordCraft/agents` (they pass with a private `HOME`); nextest (this machine's 0.9.103 is below the required 0.9.150); the app by hand

Merges `storytold/wordcraft` `main` from 729cd0a (the last sync, #65) to 2922fe56 (#6165): 340 commits, 173 of them not merges.

## What the fork gains

- **No replay of a mutation of unknown outcome** (f2d7a4fe, #1326 and #1331; 0e7dc8da, #2596). When the connection to the app fails after `wordcraft-cli mcp --connect` started sending, or the reply is lost, a state-changing request answers `outcome unknown` and is not sent again; only read-only methods (`document.inspect`, `engine.commands`, `ui.inspect`, `ui.parity`, `ui.render` or `ui.screenshot` without a `path`, and the fork's `auth`) are tried once more on a new connection. A reply that arrives but can't be read is never retried. The app cancels a request still queued when its caller's 60 s wait ends, and says whether it ran; an accept thread that can't start turns the control channel off and removes its key file; at most 64 connections wait unauthenticated. The fork's other users of the same connection (`wordcraft_mcp::Remote`) behave the same way: `mcp --http`, one connection per key, `wordcraft-cli call`, and the ACP assistant's connection to its copy.
- MCP's `insert_table` tool, and `insert.spreadsheet` taking `values`, `header` and `style` (#2242).
- View › Window across windows: Switch Windows, Arrange All, Side by Side, Synchronous Scrolling (#322).
- File › Open: removing documents from the recent list (`ui.recentRemove`, `ui.recentClear`, #2716).
- Home › Paragraph Tools (#5043), Delete Previous Sentence (Ctrl+Shift+Backspace, #5094), screen paper colour presets (#3398).
- Strict export: `--strict` on `convert` and `render`, `strict` on `file.exportPdf`/`file.exportPng`/`file.save`, and `file.strictReport` refuse missing glyphs and pictures (#6039).
- RTF footnotes, endnotes and comments (#1053); ODT fixes for gap 19; many layout, DOCX, `.doc` and paste fixes.
- Check spelling as you type is one setting for every open document (#5740); deleting an empty paragraph keeps the next one's formatting (#5929); rejecting an empty paragraph with a section break keeps the next paragraph's properties (#5667).
- Page text on Linux is hinted like FreeType's hintslight, and unhinted while zooming; dialogs with real tabs; the updater reports its progress; a Linux AppImage environment inherited from another program is ignored (#5653).
- `wordcraft-web`: `window.wordcraft`, the page command API (#5860).
- Layout unit tests use only the pinned bundled fonts (#2729, `docs/testing.md`).

## Conflicts resolved by judgment

- **`crates/mcp/src/backend.rs`:** upstream's round trip (`Failure::NotSent` or `Failure::Unknown`, `exchange_with`, `is_read_only`) with the fork's reply limit (`limit_replies`, for `mcp --http`) passed to `roundtrip_io`. `auth`, the fork's method that only says whose a key is, joined the read-only list, so the HTTP endpoint's key check is tried again on a new connection as before; `a_read_with_a_lost_reply_is_sent_again` covers it. Upstream's tests are kept; the partial-write test passes the reply limit.
- **`apps/wordcraft/src/control_server.rs`:** upstream's `start_with`, `Limits`, `Admission`, accept-thread failure and cancellable queued requests, around the fork's request reader, invite keys and `serve_copy`. The lobby and the wrong-key slow-down travel together as `Guests`, to stay within seven parameters (`too_many_arguments` is denied). A connection that joins with an invite's key releases its unauthenticated slot, as one with the window's key does, or 64 connected agents would lock the window's key out; `an_invite_s_key_frees_its_unauthenticated_slot` checks it.
- **`crates/ui-egui/src/ribbon/home.rs`** (no textual conflict): upstream's Paragraph Tools group and the fork's Assistant group together made Home fold its Styles gallery at 1440 pt, which failed `ribbon_fit::ui_tests::home_at_1440_keeps_the_styles_gallery` and `tests::clicks_on_ribbon_and_status_bar_chrome_keep_typing_in_the_document` (it clicks a Styles tile); each side alone passes both. The Assistant button moved into the Editor group, which saves the group's own frame and title: at 1440 pt Styles stays compact again, but with about 2 pt to spare, so the next group added to Home folds it.
- **`apps/wordcraft/src/main.rs`:** upstream's `try_save_prefs` (which `ui.recentRemove` and `ui.recentClear` call through `services.save_prefs`) keeps the fork's rule that a save leaves which files agents can use as `ui.json` has them, unless this window changed them and couldn't save that yet. The settings folder is protected before the AppImage message is logged.
- **`wordcraft-fonts`' `test-support` feature (`crates/fonts`, `crates/layout/Cargo.toml`):** dropped, by the fork's rule that tests and the app share one build (`docs/build-speed.md`, `cargo xtask unified`). `FontDb::init_test_fonts` is a `#[doc(hidden)]` item in every build, as BS2 did for doc's helpers; the two font tests that needed the feature always run, and `docs/testing.md` says so.
- **`crates/doc/src/change.rs`** (no textual conflict): a change doesn't carry upstream's `Document::missing_pictures`, which only a reader fills when a file opens.
- **`crates/doc/src/edit.rs`:** joining after an empty paragraph takes the next paragraph's properties and mark (upstream, #5929) and keeps its block id (fork).
- **`crates/engine/src/cmd/review/changes.rs`:** upstream's section-break case for an empty paragraph (#5667) over the fork's `Which`-filtered `ins` and `del`.
- **`crates/engine/src/cmd/file.rs`:** `file.exportPng` checks where an agent may write before upstream's strict refusal, as `file.exportPdf` does.
- **`crates/layout/src/tests.rs`:** the fork's fixtures for the #4250 footnote and widow tests (#120), which pin their font and line spacing, over upstream's refit of the same tests to its pinned fonts.
- **`crates/ui-egui/src/backstage.rs`:** upstream's full-width scrolling File page (#5282) with the fork's Share page.
- **`crates/ui-egui/src/canvas.rs`:** `CanvasView` has upstream's `rescaled` and the fork's `followed`.
- **Docs:** the read-only docs take upstream's text, and `docs/parity-checklist.md` is generated again. `docs/architecture.md` keeps both sides' revision rows, and its status line keeps the fork's latest entry with upstream's in the list before it. `docs/control-protocol.md` keeps the fork's "One request from the command line" and upstream's "Delivery and startup failures" and "View › Window", upstream's `engine.execute` row (it adds `ui.recentRemove` and `ui.recentClear` and lists every command the fork's row did), the fork's `engine.commands` and `document.inspect` rows, and a `ui.inspect` row with both `windows` and `following`. `docs/mcp.md` takes upstream's status line, keeps the fork's opening, "MCP over HTTP" and command scopes, adds upstream's "Delivery failures" and `insert_table`, and lists `insert_table` and `get_changes` among the tools that take `doc`.
- Both sides' tests are kept in the rest: `apps/wordcraft-cli/src/tests.rs`, `crates/engine/src/tests/documents.rs`, `crates/mcp/src/tests.rs`, `crates/ui-egui/src/options/tests.rs`, `crates/ui-egui/src/panes/tests.rs` and `crates/ui-egui/src/theme.rs`; `crates/engine/src/prefs.rs` keeps both sides' lenient readers; `apps/wordcraft-cli/Cargo.toml` both sides' dev-dependencies.
